splitflap.org is one relay server between a TV board and a phone remote

The Node server only pairs devices, relays commands and proxies weather.gov. All rendering, and all four display faults found in testing, live inside board.html.

Pairing takes one of two paths

A scanned QR code carries the board's 32-character secret, so the server pairs the phone at once. A typed 6-character code has no secret, so the server asks the TV to approve it. In both cases the board is then locked to one phone until it disconnects or the TV kicks it; either event issues a new code and secret.

After pairing, the phone pushes its full settings object and message text. The server keeps copies so a TV that reloads gets them back via reconnect_board.

Fifteen message types reach the server

Every companion command is relayed to the board as-is. The server only inspects a message to store settings, messages, mode and weather point for reconnects.

MessageFrom → toWhat happens
register_board / reconnect_boardBoard → serverCreates a board record with a new code and secret, or reattaches and returns saved settings, messages and mode.
pairPhone → serverMatching secret: paired at once. Code only: held as pending and pair_request sent to the board.
approve_pair / reject_pair / kick_companionBoard → serverCompletes or refuses pairing; a kick also rotates the code and secret.
update_settings / update_messagesPhone → boardStored on the server, then relayed. The board applies settings and rebuilds the grid if rows, columns or ridges change.
play_sequence / next_message / reset_board / flip_messagePhone → boardRelayed. The board starts a flip, but drops it if one is already running.
set_modePhone → boardMessages, clock (flips every second) or weather (the board polls /api/weather every 10 minutes).
companion_disconnectPhone → serverUnlocks the board and issues a new code and secret.
board_stateBoard → phoneRelayed status for the remote.

The display faults are all in the board's flip engine

Each was reproduced in headless Edge by pairing a scripted phone and comparing every cell on screen with the text sent. The board is correct when it is idle; it goes wrong when a command arrives mid-flip.

FaultWhereWhat you see
1The record of displayed characters only updates when an animation finishes, so a cancelled flip leaves it stale and later flips skip those cellsboard.html:770, 780, 935Sending HI THERE mid-flip showed HIRTHERETRAIN TO PAQIM

4Centering measures text with .length, so each colour emoji counts as two charactersboard.html:1355The last 🟩 in "DEVICE PAIRED" is cut in half and shows as a broken glyph

The lite rebuild keeps the relay and drops the rest

It lives in lite/ and runs with npm run lite on port 3001. Each cell owns its current and target character, and one loop steps every cell toward its target, so a new message mid-flip just changes targets. The same nine scripted scenarios, including the four failing ones above, all pass.
